# Engineering Lessons

Reusable lessons distilled from BeeAtlas's milestone retrospectives (v1.0–v8.0). Each recurred across several milestones; the full shipping history is preserved at [history/RETROSPECTIVE.md](history/RETROSPECTIVE.md).

## Testing & verification

- **Green ≠ covered.** A passing suite that asserts a *source* substring proves nothing about the *sink*. Assert the thing that actually ships (the emitted artifact, the rendered output), not an intermediate.
- **An adversarial code-review gate catches what a green suite can't.** Integration regressions that every unit test passes through are the ones a skeptical review pass finds. Keep the review gate even when CI is green.
- **Stale derived data lies in local UAT.** If your local artifacts are old, the page you're testing is not the page users see. Refresh derived data before trusting a manual check.
- **Audit before "complete."** A milestone-close audit catches gaps a per-phase check misses — notably S3-upload gaps where the build passed but the artifact never published.
- **Measure page weight at the server, not in the page.** Anything fetched from a Web Worker never enters the page's Resource Timing: a cold load measured with `performance.getEntriesByType('resource')` read as ~5 MB while the server was sending 37 MB, because the 32 MB database is fetched inside the SQLite worker ([ADR 0024](adr/0024-compression-is-a-build-artifact.md)). Byte-count the access log.

## Data & contracts

- **Atomic positional-contract commits, guarded by a coupling test.** When a change spans positionally-coupled files (the `occ_id` vocabulary across `src/occurrence.ts`, `src/filter.ts`, `occurrence_places.sql`), change all of them in one commit and keep a test that fails if they drift.
- **When two programs compute one answer positionally, only their outputs can be compared.** The map swatch and the map dot were each computed as `hue = index in a sorted member list`, in JS and in Python. Both re-implementations were internally correct and tested; they disagreed about the member list, so one extra member silently repainted everything after it ([ADR 0022](adr/0022-a-swatch-is-a-legend-for-dots.md)). Unit tests on either side can't see that — a test that reads the two shipped artifacts and compares them can.
- **A count column's name is not its definition.** `occurrence_count` counts the Ecdysis specimen arm, not occurrences; the map plots all five arms. Check what a column aggregates before treating it as "does this thing exist".
- **Validate the CRS of every external shapefile.** External geodata arrives in whatever projection; assume nothing, check on ingest.
- **ToS/licensing questions belong at discuss-time, not build-time.** Resolve rights before writing the pipeline that redistributes the data (this is why external authority is reconciled at build time — see [ADR 0009](adr/0009-build-time-only-external-authority.md)).
- **A "humans always win" guard that inspects the PARSED structure will silently eat whatever the parser discards.** `content/species-photos.toml`'s overwrite guard checked `description` and photo `caption` — every field a person could fill in. It still deleted the file's only piece of human reasoning, because that reasoning was a TOML *comment*, and `@iarna/toml` drops comments on parse, so they never reach the object the guard inspects ([ADR 0031](adr/0031-a-species-photo-is-a-reference-not-a-prize.md)). Nothing failed, and the loss is invisible in review unless you happen to read that region of a 4,000-line diff. Before trusting a preservation rule, ask what the round trip *throws away* — and reattach it from the raw text, not from the model.
- **A join key that is right for 84% of rows looks like missing upstream data.** The photo seeder keyed on `COALESCE(checklist.scientificName, occurrences.canonical_name)`, which is properly cased for checklist species and LOWERCASE for occurrence-only ones. 104 of 630 species missed the lookup and were recorded as "no taxon_id", then written as empty entries — indistinguishable on a species page from "iNaturalist has no licensed photo of this bee". The failure reported itself as a *content* gap, not a *join* bug, and sat that way for months. When a COALESCE draws from sources with different conventions, normalize at the seam.

## Delivery & platform

- **Internal links must end in `index.html`.** CloudFront + OAC has no directory-index behavior; a link to `/foo/` 404s. Emit `/foo/index.html`.
- **A config list of MIME types is only as right as the names in it.** `AddOutputFilterByType DEFLATE … application/javascript` looks correct and does nothing, because Apache serves `.js` as `text/javascript` — while the `text/css` beside it works, which is what makes the file read as fine. Check the name the server actually assigns (`/etc/mime.types`), and note that a per-vhost list *replaces* the global one rather than adding to it.
- **When you delete a serving layer, inventory what it was doing for you.** Both halves of the 37 MB cold load were solved before and were deleted as incidental parts of larger removals — CloudFront's auto-compression with the distribution, `_upload_hashed_gz` with the S3 upload legs ([ADR 0024](adr/0024-compression-is-a-build-artifact.md)). Neither removal was wrong; neither noticed it was carrying a second responsibility, and nothing failed when it stopped.
- **"Once per publish" is only cheap if publishes are rare.** Pre-compressing the data artifacts in `postbuild-data.mjs` was costed as ~2.9 s per publish and read as free — but that script also runs on `build:content`, which is the note-publish path, so every note write recompressed a 34 MB database that changes once a night ([ADR 0024's amendment](adr/0024-compression-is-a-build-artifact.md)). Before pricing work per-run, check every path that triggers the run.
- **A pinned interpreter is an input to the bytes, not just to the behaviour.** gzip -9 of the same database is 5,208,681 bytes under node 24.18 and 5,203,283 under node 26 — both valid, both decoding identically. Anything content-addressing a build output has to hash the pin (`.nvmrc`) or it will not see the change.
- **Target the slower browser** in any performance criterion — Firefox's WASM JIT runs ~2× slower than V8, so "fast in Chrome" is not the bar (see [ADR 0004](adr/0004-prebuilt-sqlite-artifact.md)).
- **An installed PWA and the browser tab it was installed from have SEPARATE storage buckets.** Measured on iOS 18.7: a marker written by the installed app was invisible to Safari and vice versa, in both directions — and `navigator.storage.persist()` is granted to the installed app but denied to the tab. So anything expensive to download must be gated on `display-mode: standalone`, or the user pays for it twice and the copy they paid for first is the unprotected one. This is not basemap-specific; it applies to everything the app caches ([ADR 0025](adr/0025-offline-basemap-is-a-byte-store.md), spike beeatlas-93t).
- **Spike the storage assumption before designing around it.** Every planning assumption about iOS storage was wrong in the *generous* direction: a single 238 MB `cache.put` succeeded in 905 ms, the quota was 38.4 GB rather than the feared ~1 GB, and `Blob.slice` range reads came in below the timer resolution. The design had carried an OPFS fallback and a swappable-backend seam purely to hedge those fears; measuring them deleted the abstraction instead of building it. An hour on real hardware is worth more than any amount of reasoning about Safari.
- **A path that resolves in the built tree is not a path the server will return, and a precached one takes the whole service worker down with it.** `/icons/` was the obvious home for the PWA icons: it globbed, it precached, it published into the document root, and it 404'd — Ubuntu's Apache ships `Alias /icons/ "/usr/share/apache2/icons/"` for mod_autoindex, and an Alias beats the document root. Because the icons were precached, that was not four missing images: install failed, and with no older worker the registration was **discarded**, so the site had no service worker at all — with no console error, nothing in the build log, and every offline feature silently absent. Precache lists are generated by globbing the BUILT TREE, so nothing upstream of the server can see this class of failure; check precached URLs against a running server, and when a worker fails to take control, enumerate them before looking anywhere else.
- **A service worker controls its pages at any path, but a dedicated worker outside its scope is a different client.** A scoped SW serves requests the pages it controls make at ANY path — but MapLibre's worker, served from outside that scope, had *its* fetches bypass the cache entirely (the same reason the SQLite engine runs from an inline `blob:` worker). Whether precaching an asset works depends on which thread ends up requesting it, so pin that structurally rather than assuming it.
- **A dedicated worker is its own service-worker client, matched on ITS url — including for its own imports.** The SW serves anything the pages it controls request, at any path. It does NOT serve a worker whose script lives outside its scope, and — the part that cost the most here — being merely in scope is not enough for that worker's runtime `import './sibling.mjs'`, which needs the worker itself to be a CONTROLLED client. MapLibre ships its worker as two files; offline the sibling import failed, the worker died before running a line, and everything it does (tile parsing, GeoJSON clustering, symbol layout) stopped at once with no error. Precaching both files looked correct in every test and could not work: only the worker needs them, only the worker cannot read them. Ship worker code as ONE self-contained file, and assert that in the build ([ADR 0025](adr/0025-offline-basemap-is-a-byte-store.md) amendment).
- **`navigator.onLine` is not trustworthy during page init.** On a real iPhone in airplane mode it still read `true` at 110 ms and flipped to `false` only later, so every offline guard evaluated at startup fired too early and the doomed requests went out anyway. Don't guard the network call — arrange not to need it (cache-first, revalidate on a timer), and where a guard is unavoidable, let the `offline` EVENT cancel the pending work rather than racing a poll.
- **When a bug is only reproducible on someone else's device, ship them an instrument, not another fix.** Four rounds of "read the code, find a candidate, fix it, symptom persists" ended the moment the app recorded its own requests and the device reported them. The decisive culprits were each invisible to the previous round's reasoning: one lived in a worker realm the page cannot see, another (the webmanifest and icons) was never requested by the app at all — the browser requests it. An on-device diagnostics panel is cheap and pays for itself the first time a console is unavailable.
- **In an area where failures are silent, stay on measured ground.** Everything about the basemap fails without a console error — a missing worker, an unshipped fontstack, a glyph range nobody exercised, a key that differs by one character. The refinement that is obviously better on paper (streaming into `cache.put` through a `TransformStream` instead of buffering) was deliberately not taken, because the buffering shape is the one that ran on a real phone. Prefer the verified path where a mistake will not announce itself.
